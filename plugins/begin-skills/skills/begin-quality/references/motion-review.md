# Review the operation while it moves

Use this when motion or continuous visual feedback contributes to the website's main task. Begin with the accepted direction and the visitor's actual action.

Inspect the real desktop opening height and a narrow editing viewport. Can the person reach Pause while the artwork plays? Can they see the changed object while tuning a later control? An oversized preview and a correct offscreen suspension can combine into an unusable phone editor. If a compact or sticky preview fixes that relationship, inspect its footprint, short-height behavior and boundary. Traverse actual controls with both Tab and Shift+Tab; a reverse focus move can disappear behind the preview even when forward navigation passes. Inspect the visible label and focus treatment as well as a hidden radio input's box.

For direct manipulation, compare the current pointer or range value with the painted result during the operation. A pleasant eased transition between discrete choices can feel unresponsive when applied to every drag or arrow-key step. For a discrete change, interrupt it with another choice and confirm that the latest state wins without a jump back to an old target.

For an illustrated reader, encounter the diagram through the real reading route. A transition that finishes before the diagram enters view does not communicate its intended explanation. Check direct chapter links and ordinary scrolling, with useful still explanations and accessible prose. Distinguish a conceptual diagram from a physical simulation.

For a creative loop, inspect its repeating boundary, speed and legibility without applying a short button-transition duration rule to the artwork. Test Play, Pause, held-phase inspection and a changed motion preference. Compare visible suspension with stopped scheduling. Keep an actual recording or timed observations in addition to endpoint captures.

When an artifact can be downloaded, open the actual file and compare its complete identity, units, geometry or chapter association with the selected work. If the task includes associated notes and a separate checkpoint, read a second item after keeping a first one, add a note and export it. The action's named subject must agree with the file; latest draft, selected subject and deliberately kept bookmark can have different meanings.

Record a few important findings as visible Before / proposed After / Why. State whether each is a proven behavior failure, an observed reading problem or a taste judgment. Retain a suitable type direction when the defect is scale, missing spaces, layout allocation or response behavior. Recheck the chosen repair in its actual viewport and moving state. Static geometry checks, synthetic lifecycle events, native browser observations and physical-device performance establish different facts.

For a selected object with an editor, inspect a drag of a different object before release: selected marker, name, note and coordinates should describe the same subject. Select a focused object with Enter or Space, then continue with its intended keyboard action. Focus preservation after an arrow step alone does not establish that route. Check whether a selection animation restarts on each ordinary edit.

For a real countdown or other elapsed-time task, leave long enough to cross a meaningful boundary and return. Check running and deliberately paused recovery separately. A hidden rendering loop and a continuing domain clock have different responsibilities; use actual elapsed time for that contract check.

If browser recovery is unavailable, try the other visible routes to the guide or away from the work. For small downloadable diagrams, inspect numbered markers at their actual narrow rendered size and follow a marker to its complete associated note. A readable note list does not establish readable links on the drawing.
