# Website project guidance

## People and purpose

- Website owner: the person or business this site represents.
- Visitor: a person viewing the site or taking its primary action.
- Enquirer: a visitor submitting a message, if the site has a connected form.
- Contact recipient: the owner-provided email or booking destination.
- Payment roles: define payer and receiver before adding a payment flow.

Read `BEGIN.md`, the starter's guide, and existing project instructions. Follow the current website's stack and accepted choices. Locate installed Begin resources from the actual loaded Skill path; never assume this project contains the pack.

## Make and edit

Use the website's own files and commands. Preserve current user changes, accepted content, design decisions, and contact configuration. Capture a scoped diff or recoverable copy before editing existing work. Do not regenerate a starter over this project.

Starter names, project stories, and assets are illustrative. Keep concept work identifiable. Replace identity, claims, and contact destinations with owner-provided material before representing them as real. Inspect `begin-project.json` if present; a configured destination does not prove email delivery or booking completion.

Use relevant Begin expertise when installed, and read only the resources needed for the current task. Keep secrets, private data, and local backend configuration outside public assets. Add backend/services for a concrete feature and describe their actual setup and outcomes.

## Check and continue

Run the real preview and appropriate checks. Inspect phone/desktop rendering and the primary action when tools allow. Record which checks ran and what remains unknown. A build, screenshot, contact interaction, and public deployment establish different parts of the result.

Keep `BEGIN.md` short and current. Publishing follows the user's authorized destination and actual provider setup. Preserve existing instructions when merging guidance or changing Agent hosts.
