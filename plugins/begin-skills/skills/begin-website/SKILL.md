# Begin website

Help the person make the website they have in mind. Start with their purpose and preserve their choices as the work develops. Begin supplies professional methods and editable resources; the website should have its own identity.

## Start with the work

Read existing project instructions, `BEGIN.md` when present, and the website files. Use supplied purpose, visitor action, content, and references. Ask only for missing information that changes the next result, and offer a sensible direction when the person is unsure.

Use [the task brief](references/task-brief.md) when purpose, scope, states, or completion need clarification. Reuse known requirements; a small edit rarely needs a new document. For a definition-only request, provide the agreed behavior and open decisions without implementation.

For a new site, use a new directory. Choose a suitable starter from `assets/starters/`, adapt a fitting original example available in the installed resources, or build the required structure directly. Let the content and operation determine that choice. For an existing site, follow its stack and protect current work; do not regenerate it over the existing files. Resolve resource paths relative to the installed resource, never an assumed working directory.

Read [the making workflow](references/workflow.md) when starting or resuming. Read [helper commands](references/helpers.md) when creating or previewing a starter. New starters carry project guidance samples from `assets/project-guidance/`; preserve established guidance in an existing workspace.

## Focus the current task

Choose the next result from the person's request: a first preview, a visible edit, a working action, a repair, or a publishable revision. Use relevant guidance actually available in the host and respect the person's chosen methods. Keep instructions and references limited to the current work. Missing tools or accounts affect the task's achievable outcome; identify the specific gap and continue useful work.

Refero and Mobbin can supply reference research when requested and available. The ordinary local making flow uses included resources and the owner's material; it does not depend on those subscriptions. Inspect actual images and record which decisions a reference informs.

## Keep making understandable

Show a working preview early enough for the person to react. Keep its process available through handover; record the actual restart, status and stop commands. Explain a few consequential design decisions in ordinary language. Use real supplied content; keep illustrative material identifiable. Configure the central action honestly: a contact link is different from a delivered message or completed booking.

After a requested edit, check the changed behavior and preserve accepted content, contact destinations, and design choices. Update `BEGIN.md` with the meaningful result, actual checks, and next step. Report what was observed, including unavailable tools or unfinished setup. Publishing and data collection follow the person's authorization and the selected service's real configuration.
