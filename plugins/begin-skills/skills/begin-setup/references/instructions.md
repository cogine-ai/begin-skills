# Integrate project instructions

Read the actual instruction files and their scope before writing. Use the file the host recognizes for this workspace. Preserve a nested website's existing guidance and the parent's applicable instructions. A file name does not override the host's instruction hierarchy.

Add or update one concise block in the selected file:

```markdown
## Begin project

Read `BEGIN.md` for the purpose, accepted choices, current commands, checks, and next action. Confirm commands and implementation against the current files. Preserve settled content and design. Update the note after a meaningful result; keep credentials and private data outside it.
```

Use the actual relative path when the note is elsewhere. For a repeated setup, update the existing block in place. Retain other instructions and avoid duplicating the block. If two existing files contain different rules, follow their actual host precedence and surface a material conflict rather than silently replacing them.

When migrating a prior project note, update only pointers to that record. Preserve unrelated text that happens to mention an old name. Check the result from the workspace where the Agent will read it.

Installation repair may require the host's plugin or Skills UI/CLI. Describe the supported next action from the installed release's guidance. A project configuration Skill cannot supply absent credentials, tools, or a native plugin lifecycle by writing Markdown.
