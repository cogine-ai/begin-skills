# Let the task give motion its character

Use this for a physical configurator, an illustrated reader or a moving creative artifact. Begin with the relationship the visitor needs to understand. Choose the visual direction and real typography from the subject. Motion is one part of that composition.

## Choose what movement explains

A changing arm can show a product's reach. Two separating markers can explain different roles in a story. A repeating vector model can be the work the person came to make. These ask for different treatment. A multi-second artwork cycle does not set the duration of a button response, and a short UI transition budget does not define a creative loop.

Keep consequential facts immediate. The selected identity, valid quantity, units and price should agree as soon as a choice changes. If a physical illustration interpolates, begin from what is currently painted and retarget to the newest choice. Repeated input must not queue a procession of obsolete choices. For direct manipulation, make the object follow the range or pointer value without a second chasing animation. Reserve an eased change for a discrete choice when it helps explain the new state.

## Compose the feedback with its controls

Inspect the actual opening height. A large artwork can push its own Pause control below the fold. At a narrow width, stacking the full artwork before every control can make tuning an exercise in scrolling: the visitor sees the input or the result, but cannot judge them together.

When the task needs continuous visual feedback, keep an appropriately sized current preview and its essential controls in view through that editing region. A bounded sticky surface, a compact editing arrangement or a deliberate reveal can suit the material. Preserve access to the complete output in the page or the project's accepted workspace; a compact cue does not replace the full artifact. Measure the space spent at a short phone height, check text enlargement and the supported minimum width, and inspect focus and the end of the region. Sticky is a layout choice with a cost, not a default for every website.

If enlarged text leaves too little room for both the preview and a complete option, release the persistent layout or choose a simpler arrangement. Keep the option readable and reachable. Do not undo the person's text size to preserve the pinned artwork; inspect the resulting preview/operation route and suspend a loop when its artwork actually leaves view.

The visible preview must represent the same current state. A second drawing that is stale, hidden behind a bar or excluded from playback eligibility cannot solve the problem. Test an actual later control and look at the result from that viewport, rather than declaring the layout responsive because it has no horizontal overflow.

## Let a reader encounter the explanation

Use ordinary scroll and direct chapter links when that serves the reading. Prose and useful still diagrams should survive missing animation. If a diagram transition begins when a preceding paragraph becomes active, it may finish before the diagram itself enters the phone viewport. Trigger the optional explanation where it is actually seen, or use a clear still drawing. Check the seen transition, not only the two endpoints or an observer callback.

Keep reading position, a selected note subject and a saved bookmark distinct when their meanings differ. Show the subject beside the note action. A status that says “current chapter” is ambiguous if it actually means a previously kept chapter. Follow a second chapter, add a note from there, and open the exported file to check that relationship.

## Keep a loop useful at rest

A creative loop needs Play, Pause and a way to inspect a still moment. A changed motion preference should have a defined result during playback. A still frame can remain a complete useful artifact. Suspend animation work while its actual visible surface is offscreen or the document is hidden; resume from the held phase when that is the agreed behavior. Check scheduling as well as visible stillness.

Use one valid model for the preview and the portable output. An SVG should contain the held geometry, and a playback document should retain the model, parameters and starting phase. Open actual downloaded files independently. Serialization can change self-closing SVG markup without changing geometry; compare the resulting shapes and attributes rather than raw HTML text alone.
